# Денежная модель

Только KZT, NUMERIC/Decimal с двумя знаками. API принимает суммы строками. Не более 100 000 000.00 KZT за платёж; общий остаток — NUMERIC(20,2).

Account одновременно является счётом продукта и счётом журнала. Клиентские счета — обязательства учебного банка: CREDIT увеличивает остаток, DEBIT уменьшает. SYSTEM-DEMO — активный системный счёт: его остаток равен DEBIT минус CREDIT. Он не доступен через API.

Перевод: DEBIT отправителя, CREDIT получателя на одинаковую сумму. Пополнение: DEBIT SYSTEM-DEMO, CREDIT клиента. Каждый JournalTransaction содержит ровно две строки в MVP; многопроводочные комиссии и возвраты не входят в текущую версию.

## Инварианты

- Сумма дебетов равна сумме кредитов каждого журнала.
- Кеш счёта равен его проводкам; отрицательные остатки запрещены.
- Один исполненный платёж имеет ровно один журнал с соответствующими счетами и суммой.
- Неисполненный платёж не имеет журнала.
- Журнал и проводки неизменяемы; нельзя добавлять проводки к уже закоммиченному журналу.
- Статусы EXECUTED, REJECTED и CANCELLED конечные.

Отложенные PostgreSQL-триггеры проверяют инварианты при commit. Полный откат включает журнал, оба остатка, статус, аудит и запись результата идемпотентности. База не доверяет отдельному числу cached_balance.

## Повторы

Idempotency-Key обязателен для создания платежа, PATCH и всех команд платежа. Область — пользователь + действие с UUID ресурса. Тело нормализовано serializer и сериализуется со стабильным порядком ключей. Прежний успешный результат возвращается как сохранённый ответ; изменение тела даёт 409. Ошибка без изменений откатывает запись ключа: тот же ключ можно повторить после пополнения. Повтор approve с новым ключом также не создаёт второй журнал.

## Сверка

`python manage.py reconcile` читает единый REPEATABLE READ READ ONLY snapshot: проверяет журналы, кеши и отсутствие отрицательных остатков. Ненулевой exit code означает расхождение; автоматических исправлений нет.
