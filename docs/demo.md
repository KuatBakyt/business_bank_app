# Демонстрация backend

1. Выполните установку и seed_demo по README. Все данные вымышленные.
2. Откройте Swagger и войдите бухгалтером accountant@demo.example.
3. Получите компанию, счёт DEMO-KUAT-001 и реквизиты DEMO-VECTOR-001.
4. Создайте платёж на 10 000.00 KZT, задайте Idempotency-Key, отправьте на согласование.
5. Попробуйте approve бухгалтером: ожидается 403.
6. Войдите owner@demo.example, одобрите тот же платёж. Повторите с тем же ключом: тот же ответ; повтор с новым ключом не создаёт проводки.
7. Проверьте списание через transactions под владельцем. Под partner@demo.example проверьте зачисление.
8. Закажите CSV или PDF, дождитесь READY (beat проверяет очередь каждую минуту), скачайте файл через авторизованный download.
9. Запустите reconcile. Тесты test_money.py воспроизводят конкурирующие переводы, двойное одобрение, откат и SQL-нарушения.

Деньги не резервируются до одобрения. Владелец может одобрить собственную заявку. Публичная регистрация не создаёт средства; пополнение возможно только management-командой для демонстрации.

## Резервное копирование

Из корня проекта в Linux shell:

```sh
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > bank-backup.sql
```

Восстанавливайте в отдельную чистую БД того же сервера/версии PostgreSQL. Сначала создайте БД через createdb, затем передайте SQL в psql с `-v ON_ERROR_STOP=1`. После восстановления запустите reconcile. Папку private_files сохраняйте отдельно или пересоздайте выписки.

PowerShell может менять кодировку при перенаправлении: для резервных копий используйте pg_dump -Fc внутри контейнера с последующим docker cp. Не выполняйте восстановление поверх рабочей БД.
