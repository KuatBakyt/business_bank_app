# Business Bank Flutter

Flutter Web клиент для Django API из корня репозитория. Дизайн: тёмно-синее меню, светлые панели, бирюзовые действия. Основной язык — русский. Интерфейс адаптируется к ширинам 360, 768 и 1440 px.

## Запуск

Используйте Flutter 3.47.6 stable или совместимую более новую версию. Backend сначала запустите по корневому README.

В существующем backend `.env` задайте:

```dotenv
CORS_ALLOWED_ORIGINS=http://localhost:8080,http://127.0.0.1:8080
```

После изменения пересоздайте процессы: `docker compose up -d --force-recreate`.

Из корня проекта:

```powershell
cd frontend
flutter pub get
flutter run -d chrome --web-port=8080 --dart-define=API_URL=http://localhost:8000/api/v1/
```

Адрес: http://localhost:8080. API_URL должен заканчиваться `/api/v1/`.

Войдите пользователем `owner@demo.example` и вашим DEMO_PASSWORD, заданным при seed_demo. Пользователи accountant/viewer/partner@demo.example позволяют проверить роли. Можно зарегистрировать нового пользователя и создать компанию; тестовые деньги публичная регистрация не выдаёт.

## Сценарии

- Обзор: общий баланс, счета, число платежей на согласовании, последние платежи.
- Счета: открытие владельцем, история проведённых операций, закрытие пустого счёта.
- Платежи: поиск, статусы, создание и редактирование своего черновика, отправка, согласование, отклонение с причиной, отмена.
- Выписки: счёт, период, PDF/CSV, история, обновление статуса и авторизованное скачивание.
- Участники: добавление зарегистрированного email, роль и отключение доступа владельцем.
- Аудит: история действий для владельца.

Кнопки учитывают роль, окончательную проверку всегда выполняет API. Входящий перевод виден в операциях счёта получателя; список платежей показывает исходящие платежи выбранной компании.

## Сессия и повторы

Access и refresh хранятся только в памяти. После обновления страницы войдите повторно. Конкурирующие 401 используют один refresh; сохраняется новая пара токенов. Автоматического повторения денежных запросов после сетевого сбоя нет.

Перед отправкой команды платежа сохраняются её точное тело и Idempotency-Key. При неизвестном результате новые денежные действия блокируются; баннер предлагает проверить результат с тем же ключом. Для web копия команды хранится в sessionStorage, отдельно для каждого пользователя, без токенов. После перезагрузки войдите тем же пользователем в той же вкладке для восстановления. Если браузер запрещает storage, остаётся восстановление в памяти до закрытия вкладки. При потере вкладки проверьте список платежей перед новым созданием.

Скачивание выписки сначала выполняет авторизованный GET, затем передаёт байты браузеру. JWT не попадает в ссылку. Деньги форматируются через BigInt в копейках, без double.

## Проверки

```sh
flutter analyze --no-fatal-infos
flutter test
flutter build web --release --no-web-resources-cdn --dart-define=API_URL=https://your-api.example/api/v1/
```

CI запускает unit/widget тесты, проверку живого Django API с PostgreSQL, сверку балансов и сборку web. Тестовые скриншоты создаются отдельным запуском widget tests с CAPTURE_UI; это снимки приложения с вымышленными данными.

Нативные Android/iOS проекты пока не созданы. Веб-загрузка файлов реализована через package:web; нативная выдача файлов требует отдельной реализации.
